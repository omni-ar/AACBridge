\section{Implementation}
\label{sec:implementation}

The AACBridge system was implemented utilizing a hybrid orchestration stack to balance high-level sensor polling with low-level tensor mathematics. The orchestration layer was authored in Kotlin leveraging Android Coroutines, while the core inference engine was built on the C++ \texttt{llama.cpp} backend. The system targets Android API Level 36, strictly compiled against the \texttt{arm64-v8a} Application Binary Interface (ABI) to guarantee access to Snapdragon NEON SIMD hardware acceleration.

\subsection{JNI Boundary Contract and Memory Ownership}
\label{subsec:architecture}

A critical architectural constraint in real-time edge processing is minimizing the overhead of the Java Native Interface (JNI). Attempting to serialize and transfer a 100MB+ multidimensional tensor buffer from the JVM into native C++ memory triggers massive \texttt{byte[]} array allocations, invoking severe Garbage Collection (GC) pauses that immediately violate the sub-500ms TTFT budget.

To resolve this, AACBridge enforces a strict scalar-only JNI contract. The Kotlin \texttt{LlamaBridge} object passes only lightweight \texttt{jstring} paths and primitive integers. The \texttt{llama.cpp} runtime maintains absolute ownership of the tensor arena within the native heap. Large language model weights (e.g., Qwen2.5-0.5B-Instruct in \texttt{.gguf} format) are mapped directly from the device's secondary flash storage into native memory using \texttt{mmap}, explicitly bypassing the Android \texttt{AssetManager} which enforces file size limitations that crash during application startup.

\subsection{The KV Cache sequence ID (\texttt{seqId}) Lifecycle}
\label{subsec:seqid}

The JVM orchestration layer strictly differentiates between semantic context (the \texttt{ContextState}) and native memory location. The native engine owns the KV memory through a series of fixed slots called sequence IDs (\texttt{seqId}). 

To respect the $\sim$2GB background service memory budget dictated by the Android OS, the \texttt{KVCacheManager} restricts the native ring buffer to \texttt{MAX\_ACTIVE\_KV\_STATES = 3}. The JVM initializes a concurrent pool of available IDs ($[0, 1, 2]$). When the \texttt{StateRouter} nominates a context for pre-loading, the manager maps that \texttt{ContextState} to an available \texttt{seqId} slot and issues the \texttt{Java\_loadKVCache()} JNI hook. 

Notably, there is no explicit API to free a native KV cache. Executing continuous \texttt{malloc} and \texttt{free} commands for gigabyte-scale tensors causes rapid memory fragmentation. Instead, when a state is evicted, its \texttt{seqId} is returned to the pool; subsequent cache loads simply overwrite the existing native memory buffer in place.

\subsection{Concurrency Guarantees and Safe Eviction}
\label{subsec:concurrency}

Because the asynchronous \texttt{DriftDetector}, the \texttt{StateRouter}, and the UI-driven Inference Engine run on isolated background threads, aggressive cache eviction risks severe JNI race conditions. Deleting a binary file from flash storage while \texttt{llama.cpp} attempts a concurrent read triggers an \texttt{IOException} that permanently collapses the native bridge. 

To ensure thread safety without resorting to global system locks, the backend implements a four-layer lock-free orchestration model:
\begin{enumerate}
    \item \textbf{Per-State Mutex Isolation:} The \texttt{CacheMutexRegistry} enforces synchronization solely at the individual state level, allowing parallel manipulation of orthogonal contexts.
    \item \textbf{Atomic Acquisition:} State residency checks and \texttt{refCount} increments are executed atomically under the state mutex.
    \item \textbf{Safe Eviction Proof:} Eviction logic first marks a state's volatile \texttt{isActive} boolean to false, preventing new inference acquisitions. It then releases the mutex and polls the \texttt{refCount}. Because \texttt{isActive} is false, the \texttt{refCount} is mathematically guaranteed to drain monotonically to zero, at which point file manipulation is safely authorized.
    \item \textbf{Lock-Free Release:} Because of the monotonic drain proof, the \texttt{releaseState()} function operates lock-free, utilizing hardware atomic decrements to minimize overhead.
\end{enumerate}

\subsection{Android Lifecycle Orchestration}
\label{subsec:orchestration}

Standard Android Geofencing APIs fail to trigger if a device reboots while physically located inside the defined boundary, breaking the predictive caching model. To guarantee context priming, orchestration begins immediately at the OS level. 

A \texttt{BootReceiver} intercepts the \texttt{ACTION\_BOOT\_COMPLETED} broadcast, utilizing Android's \texttt{goAsync()} mechanism to preserve the process lifecycle for 10 seconds. This triggers the \texttt{ActiveSweep} daemon, which concurrently spawns Kotlin Coroutines to fetch the \texttt{LocationManager}'s best hardware provider alongside a strictly bounded 3000ms BLE topology scan. The resulting \texttt{SensorSnapshot} is fed synchronously into the \texttt{StateRouter}, dispatching the top-3 ranked caching operations to native background threads to avoid Application Not Responding (ANR) exceptions.

\subsection{Implementation Limitations and Current Assumptions}
\label{subsec:limitations}

While the Phase 2 backend orchestration is functionally complete, several architectural assumptions remain pending empirical validation in Phase 3 benchmarking:
\begin{itemize}
    \item \textbf{In-Memory Persistence:} The current orchestration relies on an \texttt{InMemoryStateRepository}. Transitioning to SQLite via Room DAOs is required before final latency benchmarking to capture true IO overhead.
    \item \textbf{The \texttt{saveKVCache()} Lifecycle:} The \texttt{loadKVCache()} JNI boundary is fully automated, but the exact timing and ownership of calling \texttt{saveKVCache()} to serialize dynamically computed states back to flash memory remains unresolved. If states are not explicitly serialized, cold start recovery operations will fail.
    \item \textbf{BLE-Bypass Accuracy Degradation:} The \texttt{DriftDetector} explicitly bypasses BLE scanning during its 15-minute polling interval to conserve mobile battery life. While relative hysteresis deltas remain mathematically valid, the absolute predictive accuracy of the background sweep is temporarily degraded.
    \item \textbf{Overwrite Stability:} The reliance on \texttt{seqId} native overwriting rather than explicit cache freeing assumes that \texttt{llama.cpp} safely handles internal tensor sizing mismatches between sequential contexts. This requires extensive empirical stress testing on the target Snapdragon hardware.
\end{itemize}
