\section{Implementation}
\label{sec:implementation}

The AACBridge system was implemented utilizing a hybrid orchestration stack to balance high-level sensor polling with low-level tensor mathematics. The orchestration layer was authored in Kotlin leveraging Android Coroutines, while the core inference engine was built on the C++ \texttt{llama.cpp} backend. The system targets Android API Level 36, strictly compiled against the \texttt{arm64-v8a} Application Binary Interface (ABI) to guarantee access to Snapdragon NEON SIMD hardware acceleration.

\subsection{JNI Boundary Contract and Memory Ownership}
\label{subsec:architecture}

A critical architectural constraint in real-time edge processing is minimizing the overhead of the Java Native Interface (JNI). Attempting to serialize and transfer a 100MB+ multidimensional tensor buffer from the JVM into native C++ memory triggers massive \texttt{byte[]} array allocations, invoking severe Garbage Collection (GC) pauses that immediately violate the sub-500ms TTFT budget.

To resolve this, AACBridge enforces a strict scalar-only JNI contract. The Kotlin \texttt{LlamaBridge} object passes only lightweight \texttt{jstring} paths and primitive integers. The \texttt{llama.cpp} runtime maintains absolute ownership of the tensor arena within the native heap. Large language model weights (e.g., Qwen2.5-0.5B-Instruct in \texttt{.gguf} format) are mapped directly from the device's secondary flash storage into native memory using \texttt{mmap}, explicitly bypassing the Android \texttt{AssetManager} which enforces file size limitations that crash during application startup.

\subsection{The KV Cache sequence ID (\texttt{seqId}) Lifecycle}
\label{subsec:seqid}

The JVM orchestration layer strictly differentiates between semantic context (the \texttt{ContextState}) and native memory location. The native engine owns the KV memory through a series of fixed slots called sequence IDs (\texttt{seqId}). 

To respect the $\sim$2GB background service memory budget dictated by the Android OS, the \texttt{KVCacheManager} restricts the native ring buffer to \texttt{MAX\_ACTIVE\_KV\_STATES = 3}. The JVM initializes a concurrent pool of available IDs ($[0, 1, 2]$). When the \texttt{StateRouter} nominates a context for pre-loading, the manager maps that \texttt{ContextState} to an available \texttt{seqId} slot and issues the \texttt{Java\_loadKVCache()} JNI hook. 

Notably, there is no explicit API to free a native KV cache. Executing continuous \texttt{malloc} and \texttt{free} commands for gigabyte-scale tensors causes rapid memory fragmentation. Instead, when a state is evicted, its \texttt{seqId} is returned to the pool; subsequent cache loads simply overwrite the existing native memory buffer in place.

\subsection{Concurrency Guarantees and Device Stabilization}
\label{subsec:concurrency}

Because the asynchronous \texttt{DriftDetector}, the \texttt{StateRouter}, and the UI-driven Inference Engine run on isolated background threads, parallel cache manipulation risks severe JNI race conditions. Early iterations of the architecture encountered native \texttt{SIGBUS} memory mapping crashes when the inference engine attempted to access native context arrays while the daemon was actively evicting them.

To guarantee operational stability, AACBridge implements a synchronized concurrency model anchored by a single shared \texttt{engineLock} (a JVM \texttt{ReentrantLock}). This lock strictly serializes access across the JNI boundary for three primary orchestration components:
\begin{enumerate}
    \item \textbf{\texttt{MainActivity}:} Acquires the lock during real-time inference to prevent memory displacement while the LLM generates tokens.
    \item \textbf{\texttt{KVCacheManager}:} Acquires the lock during state eviction and \texttt{seqId} swaps to ensure files are not deleted out from under an active inference session.
    \item \textbf{\texttt{ContextPrimerImpl}:} Acquires the lock when pre-computing environmental caches in the background.
\end{enumerate}
Through the implementation of the \texttt{engineLock}, \texttt{SIGBUS} native crashes were completely eliminated, establishing a stabilized baseline for latency benchmarking.

\subsection{Android Lifecycle Orchestration and Context Priming}
\label{subsec:orchestration}

Standard Android Geofencing APIs fail to trigger if a device reboots while physically located inside the defined boundary, breaking the predictive caching model. To guarantee context priming, orchestration begins immediately at the OS level. 

A \texttt{BootReceiver} intercepts the \texttt{ACTION\_BOOT\_COMPLETED} broadcast, utilizing Android's \texttt{goAsync()} mechanism to preserve the process lifecycle for 10 seconds. This triggers the \texttt{ActiveSweep} daemon, which concurrently spawns Kotlin Coroutines to fetch the \texttt{LocationManager}'s best hardware provider alongside a strictly bounded 3000ms BLE topology scan. The resulting \texttt{SensorSnapshot} is fed synchronously into the \texttt{StateRouter}, dispatching the top-3 ranked caching operations to the \texttt{ContextPrimerImpl}.

The \texttt{ContextPrimerImpl} manages the full pre-computation lifecycle. Gated safely behind a \texttt{modelReady} boolean (which prevents execution until the \texttt{llama.cpp} native backend successfully maps the \texttt{.gguf} weights), the primer executes a strict sequential pipeline: it \texttt{prime}s the native LLM with the prompt, calls \texttt{saveKVCache} to serialize the native tensors into a persistent \texttt{.bin} file on the flash storage, and finally prepares the state for instantaneous retrieval via \texttt{loadKVCache} during user interaction.

\subsection{Implementation Persistence Strategies}
\label{subsec:limitations}

For the evaluation and benchmarking phase of the system, AACBridge employs a \texttt{SeededStateRepository}. This repository serves deterministic, hardcoded semantic context profiles mapped to rigid environmental identifiers. Deploying a deterministic data store directly unblocks the prefill, save, and load pipeline required for precise Time To First Token (TTFT) performance measurements. While dynamic runtime context creation necessitates future architectural enhancements such as Android Room (SQLite) DAOs, the \texttt{SeededStateRepository} fully satisfies the persistence requirements of the current system architecture without introducing unnecessary database ORM overhead.
